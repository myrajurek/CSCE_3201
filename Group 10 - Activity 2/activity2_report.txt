ACTIVITY 2 REPORT – METACRITIC SCORE PREDICTION AGENT
================================================================

PROJECT TITLE
-------------
Metacritic Score Prediction Agent


DATASET AND PREDICTION TASK
----------------------------
Dataset: metacritic_games.csv
The dataset contains video game records from Metacritic, including
critic scores (metascore), user scores (userscore), platforms, and
genres.

Prediction Task: Predict the metascore (0-100) for a video game
given its userscore, platform, and genre(s). This is a regression
task because the target variable is a continuous numeric value.


SUMMARY OF PHASE 1 MODEL AND PREPROCESSING PIPELINE
-----------------------------------------------------
The Phase 1 pipeline (phase1_pipeline.py) was built in Activity 1
and reused here without modification.

Preprocessing:
- "tbd" strings in the userscore column were converted to NaN using
  pd.to_numeric(errors='coerce'), then rows with missing values were
  dropped using dropna().
- Genres were multi-hot encoded using str.get_dummies(sep=","),
  producing one binary column per unique genre tag.
- Platforms were one-hot encoded using pd.get_dummies(drop_first=True),
  producing one binary column per platform.

Model: LinearRegression (scikit-learn)
- Train/Test Split: 80% training, 20% testing (random_state=42)
- Evaluation Metrics: Mean Squared Error (MSE) and R-squared (R2)

Saved Artifacts:
- model.pkl: the fitted LinearRegression object
- feature_cols.pkl: ordered list of column names used at training time


DESCRIPTION OF THE AGENT'S SINGLE TASK
----------------------------------------
The agent has one task: collect the three required inputs from the
user (userscore, platform, genres), pass them to the Phase 1 model,
and return a predicted metascore with a plain-language explanation.

If any input is missing from the user's message, the agent asks only
for the missing value. Once all three are collected, the agent outputs
a structured JSON trigger that the local pipeline detects, runs the
prediction, and sends the result back to the agent for explanation.

AGENT INSTRUCTIONS (SYSTEM PROMPT)
------------------------------------
The following system prompt was used to configure the agent's behaviour:

"You are a Metacritic score prediction assistant.
Your job is to collect exactly three pieces of information from the user:
  1. userscore  - a number between 0 and 10
  2. platform   - the gaming platform (e.g. PlayStation 4, PC, Xbox One, iOS)
  3. genres     - one or more genres (e.g. Action, RPG, Puzzle, Strategy)

If any of the three are missing, ask only for the missing one(s).
Once you have all three, respond with ONLY this exact format and nothing else:
EXTRACT_FEATURES_JSON {"userscore": <float>, "platform": "<str>", "genres": ["<str>", ...]}"


HOW THE AGENT EXTENDS THE PHASE 1 WORK
----------------------------------------
Phase 1 produced a trained regression model but had no user interface.
Activity 2 wraps that model in a conversational agent so that any user
can get a prediction without writing code or understanding machine learning.

The extension works in three steps:
1. The agent gathers inputs through natural conversation, removing the
   need for the user to know the exact feature names or encoding format.
2. The local pipeline (agent_pipeline.py) encodes the collected inputs
   using the exact same one-hot and multi-hot logic as Phase 1, ensuring
   the feature vector matches what the model was trained on.
3. The agent translates the numeric prediction into a plain-language
   explanation, making the result accessible to non-technical users.


ONE STRENGTH
-------------
Title: Consistent input validation and guided data collection

The agent reliably identified which of the three required inputs were
missing and asked only for the specific missing value, never re-asking
for information already provided. This made the interaction feel natural
and efficient. Without this guidance, a non-technical user would likely
send incomplete data and receive an error or a meaningless prediction.


ONE FAILURE CASE
-----------------
Title: Unrecognised platform names are silently ignored

When a user provided a platform not present in the training data (e.g.
"Steam Deck" or "PlayStation 5"), no matching one-hot column existed in
feature_cols.pkl, so the platform value was silently set to zero across
all platform columns. The prediction continued without warning, appearing
more confident than it should have been. This is a real failure because
platform can be a meaningful signal in the model.


REFLECTION
----------
Building an AI agent on top of the Phase 1 model revealed how different
the challenges of deployment are from the challenges of modelling. In
Activity 1, success meant minimising MSE and maximising R-squared. In
Activity 2, success meant making the model accessible to a user who may
never have heard of R-squared. The most important lesson was that a model
is only as useful as the interface that wraps it — a perfectly trained
model hidden behind a confusing input process serves nobody.

The main technical challenge was aligning new user input with the encoding
produced by Activity 1. Because pd.get_dummies was applied to the full
training dataset at training time, any input using a slightly different
string (e.g. "PS4" instead of "PlayStation 4") would silently produce a
zero rather than raising an error. A future improvement would add a
normalisation step that maps common synonyms to canonical training-set
values before encoding. Additionally, replacing the single-point Linear
Regression estimate with a prediction interval would allow the agent to
communicate uncertainty honestly, giving users a more trustworthy answer.
